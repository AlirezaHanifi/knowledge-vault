Incremental loading and backfills

An Incremental Loader brings in only what is new since the last run. It finds new rows with a delta column such as ingestion time, or by reading the partition for the execution hour. Both look the same in normal runs. They differ when rows are deleted and when you backfill.

Illustrates “Pattern: Incremental Loader” (pp. 12–16). The book describes the delta-column and time-partitioned implementations, hard deletes vs soft deletes, and how an unbounded delta-column backfill turns into a full load unless the ingestion window is bounded. The source rows are generated (seeded, 2–5 per hour). Delta-column runs append new rows and apply soft-delete flags. A partition run copies its partition, deletions included, as aws s3 sync … --delete does in the book. Implementation is the vault's own.

    What to notice
    
  
      
    
    • Hard deletes are invisible to a delta column. Run a few hours, delete a row, then run again. Bronze keeps the row because nothing new carries the deletion. Turn on soft deletes and the deletion arrives as an update.
      • 
    
    • An unbounded backfill is a full load. After eight hours, backfill hour 1 with the unbounded delta column. It reads everything from hour 1 up to now. The bounded window reads one hour.
      • 
    
    • Partitions are naturally bounded. A partition run reads exactly its hour. Syncing that partition also brings in deletions made inside it.
