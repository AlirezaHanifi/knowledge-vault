Bucket pruning and Z-order skipping

Partitioning breaks down for high-cardinality columns. The Bucket pattern groups keys with hash(key) % buckets, so a query on one key opens one bucket. The Sorter orders rows so that each data block covers a narrow range, and min/max statistics let the engine skip blocks. A lexicographic sort helps only queries on its first column. A Z-order curve helps both columns.

    What to notice

    • Filter on x only. The lexicographic layout reads only the matching blocks, because its blocks are slices of x.
    • Filter on y only. The lexicographic layout now reads every block: each block covers all y values. This is the composite-sort-key trap of Figure 8-6. Z-order reads half of them.
    • A small box on both columns favours Z-order, as in Figure 8-5. Its blocks are compact squares and rectangles.
    • Buckets prune by key. A query on one user_id opens one bucket. A join avoids the shuffle only when both tables use the same bucket count.
