Reproducible or not?

Replaying a call reproduces it only if two things hold: the captured context is what the function really saw, and any external data source answers the same way when you replay. Immutable data guarantees the first; an immutable database, or debugging alone on your machine, gives the second.

Illustrates sections 15.4–15.5 (pp. 323–330): dumpData writes asynchronously, Dave’s worry about data modified while it’s written and why immutability rules it out, and Theo’s answers on external data: immutable databases that query a snapshot, and local debugging where you’re the only user.       What to notice
      
  
        
    
      • Immutable in-memory data: the code that runs after the call creates a new version instead of changing the catalog, so the asynchronous dump writes exactly what the function received.
        • 
    
      • Mutable data lets the dump race the code that follows: the file can hold a catalog the function never saw, and the replay no longer matches.
        • 
    
      • External sources are outside the function context. An immutable database queried at the original time gives the same answer; a mutable one shared with others may not. Alone on your laptop, it usually does.
