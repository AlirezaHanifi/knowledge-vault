commit و undo

هر mutation در DOP دو فاز دارد. محاسبه تابعی سرراست است که version بعدی را برمی‌گرداند یا خطا می‌دهد. commit بین همه‌ی mutationها مشترک است: version بعدی را اعتبارسنجی می‌کند و state سیستم را جلو می‌برد. نگه داشتن ارجاع به version قبلی undo را ساده می‌کند.

تصویری از بخش‌های ۴.۵ تا ۴.۷ (listingهای ۴.۷ تا ۴.۱۰، صص. ۸۳–۸۹): کلاس‌های System و SystemState، اعتبارسنجی کل سیستم هنگام commit و undo با previousSystemData. نام عضوها، مثال قرض نامعتبر و حالت پشته از vault است؛ کتاب در ص. ۸۸ به پشته اشاره می‌کند. پیاده‌سازی از خود vault است.

آبی: version که systemData به آن اشاره می‌کند. خط‌چین: version که هنوز برای undo نگه داشته شده. کم‌رنگ و خط‌خورده: دیگر کسی به آن اشاره نمی‌کند و garbage collector جمعش می‌کند.

    به چه چیزی دقت کنید

    • محاسبه خودش ممکن است شکست بخورد: اضافه کردن عضوی که از قبل هست خطای «Member already exists.» می‌دهد (ص. ۷۹) و چیزی commit نمی‌شود.
    • commit می‌تواند نتیجه‌ی محاسبه را رد کند: قرضی که نسخه‌اش امانت‌رفته علامت نخورده state نامعتبری است. این بررسی یک بار برای کل سیستم انجام می‌شود، نه در هر کلاس.
    • یک ارجاع قبلی یعنی یک undo. دو بار undo کنید و همان‌جا می‌مانید. با پشته‌ای از ارجاع‌ها هر version را می‌شود برگرداند و structural sharing نگه‌داشتنشان را ارزان می‌کند.
