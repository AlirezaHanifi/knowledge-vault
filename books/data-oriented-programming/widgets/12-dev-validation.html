Validation inside the system

Boundary validation guards production. Inside the system, Dave validates a function’s arguments and its return value against schemas, but only when dev() is true: in every environment except production. A mistake then fails early, with a message that says what is wrong and where.

Illustrates sections 12.1–12.2 (listings 12.1–12.11, pp. 248–257): the catalog, book, book-item and author schemas, the tuple schema with prefixItems, homogeneous maps with additionalProperties, and the two dev-only checks. The catalog combines listing 15.10’s books and authors with listing 14.10’s book items; the author IDs and purchase dates are the vault’s. Error texts follow Ajv’s style. Implementation is the vault’s own.

    What to notice
    
  
      
    
    • In production, most mistakes slip through quietly: a number as the query or swapped arguments just return [], and a missing author returns undefined in the names.
      • 
    
    • A book without a title crashes in production with a JavaScript TypeError deep inside the filter, the kind of unclear error Dave struggled with. In dev, the argument check names the exact path.
      • 
    
    • The return-value check catches what the argument check can’t: valid arguments that still make the function return data that breaks its contract.
