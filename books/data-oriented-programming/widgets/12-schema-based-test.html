Schema-based tests

With a schema for the arguments and one for the return value, a unit test writes itself: generate random data that conforms to the input schema, call the function, and check the output against the output schema. Random catalogs cite authors that don’t exist, and that is exactly the bug the test finds.

Illustrates section 12.5 (figure 12.3; listings 12.19–12.29, pp. 262–268): random data from JSON Schema Faker, the test that returns true or false, the query built from the first letter of the first book’s title, the logged error, and the "Not available" fix. The generator here is the vault’s small stand-in for JSON Schema Faker: lorem-style words, seeded, with one to four books. Implementation is the vault’s own.

The test (after listing 12.24)
function searchBooksTest() {
  var catalogRandom = JSONSchemaFaker.generate(catalogSchema);
  var queryRandom = firstLetterOfFirstTitle(catalogRandom);
  try {
    Catalog.searchBooksByTitle(catalogRandom, queryRandom);  // throws in dev
    return true;
  } catch (error) {
    console.log(error);
    return false;
  }
}

    What to notice
    
  
      
    
    • Random IDs almost never line up: a book’s authorIds and the keys of authorsById are generated independently, so most matching books have unknown authors and authorNames holds undefined.
      • 
    
    • A test can pass by luck: when the matching books have no author IDs at all. Running many seeds shows how often.
      • 
    
    • With the fix, a missing author becomes "Not available", a string, so every run passes the return-value check.
