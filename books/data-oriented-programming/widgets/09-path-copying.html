کپی مسیر

هر فهرستی persistent یک درخت است. عوض کردن یک عضو تنها nodeهای روی مسیر از ریشه تا آن برگ را کپی می‌کند؛ و باقی با version پیشین شریک است. ضریب شاخه عمق را با اندازه‌ی هر node کپی‌شده بده‌بستان می‌کند.

تصویری از بخش ۹.۲ (شکل‌های ۹.۲ و ۹.۳، صص. ۱۷۹–۱۸۳): شکستن فهرستی به نیم و ربع، عمق log₂ N در برابر log₃₂ N، و اینکه چرا ۳۲ به cache lineها می‌خورد. آن vector ۶۴عضوی و این نقاشی مال vault است. پیاده‌سازی مال خود vault است.

درخت

نارنجی: nodeهایی که آن به‌روزرسانی کپی کرده، یعنی همان مسیر. خاکستری: شریک با version پیشین.

گزارش رویداد

    به چه چیزی نگاه کنید

    • تنها آن مسیر کپی می‌شود: یک node برای هر سطحی. با ضریب شاخه‌ی ۲ آن ۶ node کوچک برای ۶۴ عضو است؛ و با ۳۲ دو node پهن‌تر.
    • عضوهای کپی‌شده در هر به‌روزرسانی عمق ضرب در ضریب شاخه است: این‌جا ۲ × ۶ = ۱۲ و ۴ × ۳ = ۱۲ و ۳۲ × ۲ = ۶۴. nodeهای پهن‌تر عضوهای بیشتری کپی می‌کنند ولی به nodeهای خیلی کم‌تری دست می‌زنند.
    • حرف کتاب برای ۳۲ همان CPU است: کپی یک آرایه‌ی ۳۲خانه‌ای جفتی دسترسی cache است، در حالی که دواندن میان nodeهای کوچک زیاد یعنی دسترسی‌های جدای زیاد به حافظه.
