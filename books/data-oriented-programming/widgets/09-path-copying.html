Chapter 9 · Persistent data structures

Path copying

A persistent list is a tree. Changing one element copies only the nodes on the path from the root to that leaf; everything else is shared with the previous version. The branching factor trades depth against the size of each copied node.

Illustrates section 9.2 (figures 9.2–9.3, pp. 179–183): splitting a list into halves and quarters, depth log₂ N versus log₃₂ N, and why 32 suits cache lines. The 64-element vector and the drawing are the vault’s. Implementation is the vault’s own.

    What to notice

    • Only the path is copied: one node per level. With branching factor 2 that is 6 small nodes for 64 elements; with 32 it is 2 wider ones.
    • Elements copied per update is depth × branching factor: 2 × 6 = 12, 4 × 3 = 12, 32 × 2 = 64 here. Wider nodes copy more elements but touch far fewer nodes.
    • The book’s argument for 32 is the CPU: copying one 32-slot array is a pair of cache accesses, while chasing many small nodes means many separate memory accesses.
