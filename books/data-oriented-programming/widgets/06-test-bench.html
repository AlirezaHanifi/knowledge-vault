Test bench

A DOP test case is three steps: build dataIn, build dataOut, and compare f(dataIn) with dataOut using _.isEqual. For a function that returns JSON, compare data, not strings: the same data can serialize with its fields in any order.

Illustrates sections 6.1 and 6.3 (listings 6.1–6.2 and 6.12–6.20, pp. 111–125): _.isEqual, comparing parsed JSON, and the lowercase query that finds a bug. The second book and the field-order switch are the vault’s. Implementation is the vault’s own.

    What to notice
    
  
      
    
    • Comparing strings fails for the wrong reason: change the field order of the serialized output and identical data no longer compares equal. Parse with JSON.parse, then compare with _.isEqual.
      • 
    
    • The lowercase case fails for the right reason: includes is case-sensitive. Finding that bug is the point of the test.
      • 
    
    • The fix changes the code, not the tests: lowercase both the query and the title, and every case passes in either comparison mode.
