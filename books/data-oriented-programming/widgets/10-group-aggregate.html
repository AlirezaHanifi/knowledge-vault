Group and aggregate

A join returns one row per book and author: three rows for two books. Joe reshapes them in the application with two generic functions: _.groupBy on the ISBN, then aggregateField, which collects author_name into authorNames and keeps the first row as the basis.

Illustrates section 10.4 (listings 10.17–10.26, table 10.6, figure 10.3, pp. 211–218). The rows are table 10.6’s; the extra rows are the vault’s. Implementation is the vault’s own.

    What to notice
    
  
      
    
    • groupBy returns a map from ISBN to that book’s rows; the keys aren’t needed afterwards, so _.values keeps only the groups.
      • 
    
    • aggregateField is generic: aggregateFields(rows, "isbn", "author_name", "authorNames") would aggregate any field of any entity.
      • 
    
    • Adding rows changes nothing in the code: a new co-author lengthens one list, a new book adds one group.
