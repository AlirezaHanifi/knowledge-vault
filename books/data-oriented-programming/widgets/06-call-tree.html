Tree of function calls

To unit test a DOP function, draw its tree of function calls down to functions outside your code base. Test bottom-up: deep nodes get many cases with simple data; nodes near the root get few cases with richer data, assuming their children already work.

Illustrates sections 6.2 and 6.4 (figures 6.1–6.5, table 6.2, pp. 113–131): the search tree, the add-member tree, minimal data valid in context (listing 6.7) and the depth rule. The per-node case counts are the vault’s reading of the book’s examples. Implementation is the vault’s own.

      What to notice

      • Validity depends on the context: the minimal catalog for authorNames has only authorsById, and that is perfectly valid there, though not for searchBooksByTitle.
      • Deeper nodes, more cases, simpler data: authorNames gets empty, one-ID, two-ID, unknown-ID and empty-catalog cases; bookInfo gets one.
      • Mutations test the state they produce: UserManagement.addMember gets an empty-state, an existing-members and a negative case; the stateful System.addMember is tested through SystemState.get().
