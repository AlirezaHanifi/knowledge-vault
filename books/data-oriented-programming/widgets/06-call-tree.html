درخت صدا زدن تابع‌ها

پیش از unit test، درخت صدا زدن تابع‌ها را تا تابع‌های بیرون کدبیس بکشید. node عمیق‌تر: داده‌ی ساده‌تر و موردهای بیشتر. نزدیک ریشه: داده‌ی غنی‌تر و موردهای کمتر، چون فرض می‌شود تابع‌های پایین‌تر از قبل تست شده‌اند.

تصویری از بخش‌های ۶.۲ تا ۶.۴ (صص. ۱۱۳–۱۳۲): درخت جست‌وجو (شکل ۶.۱، ص. ۱۱۴)، درخت افزودن عضو (شکل ۶.۵، ص. ۱۲۶)، داده‌ی کمینه که در زمینه‌ی خودش معتبر است (listing ۶.۷، ص. ۱۱۷) و جدول ۶.۲ (ص. ۱۲۱). موردهای تست همان موردهای listingهای کتاب‌اند؛ نوشتن کوتاهشان از vault است. پیاده‌سازی از خود vault است.

تابع کدبیس، تست می‌شود (عدد: تعداد موردها)بیرون کدبیس: برگ درختgeneric، جداگانه تست می‌شود

جدول ۶.۲ برای همین درخت: عمق در برابر تعداد موردها

node انتخاب‌شده

به چه چیزی دقت کنید

  • اعتبار داده به زمینه بستگی دارد: catalog کمینه فقط authorsById را دارد. برای authorNames کاملاً معتبر است ولی برای searchBooksByTitle نه (ص. ۱۱۷).
  • nodeهای عمیق‌تر، موردهای بیشتر و داده‌ی ساده‌تر: authorNames هفت مورد متفاوت دارد و bookInfo فقط یکی، چون فرض می‌شود تابع‌هایی که صدا می‌زند درست کار می‌کنند (ص. ۱۲۰).
  • تست mutation سخت‌تر از query است: ورودی و خروجی هر دو state سیستم‌اند (ص. ۱۲۷)، و System.addMember اصلاً چیزی برنمی‌گرداند؛ پس state بعد از اجرا را با _.isEqual می‌سنجیم (ص. ۱۳۲).
