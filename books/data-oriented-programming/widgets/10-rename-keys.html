Rename keys

Database columns are in snake case; the JSON response wants bookTitle and publicationYear. Instead of a function per query, Theo writes one generic renameResultKeys(rows, keyMap). It works because fields are accessed by string: fields are first-class citizens.

Illustrates section 10.3, Simple data manipulation (listings 10.11–10.16, pp. 207–211): the three options, renameKeys with _.reduce, _.set and _.omit, and its reuse on users. Rows from tables 10.1 and listing 10.16. Implementation is the vault’s own.

The generic code (listing 10.14)
function renameKeys(map, keyMap) {
  return _.reduce(keyMap, function(res, newKey, oldKey) {
    var value = _.get(map, oldKey);
    var resWithNewKey = _.set(res, newKey, value);
    var resWithoutOldKey = _.omit(resWithNewKey, oldKey);
    return resWithoutOldKey;
  }, map);
}
function renameResultKeys(results, keyMap) {
  return _.map(results, function(result) { return renameKeys(result, keyMap); });
}

    What to notice
    
  
      
    
    • One function, any entity: the same code renames book columns and user fields, because it never names a field itself.
      • 
    
    • Unmentioned fields stay as they are; only the keys in the key map move.
      • 
    
    • A key that isn’t in the row still gets its new name, with an undefined value, because renameKeys doesn’t check. The vault’s widget shows it; decide whether that is what you want.
