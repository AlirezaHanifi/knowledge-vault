Chapter 7 · Basic data validation

JSON Schema playground

In DOP the schema is separate from the representation: data is a plain map, and a schema, itself just data, says what shape it should have. Validate at the system’s boundaries and report what went wrong in detail.

Illustrates sections 7.2, 7.3 and 7.5 (listings 7.2–7.23, pp. 144–159): the search request and response schemas, the database response with and without additionalProperties: false, and Ajv’s error details. The validator is the vault’s small subset of JSON Schema, not Ajv; its messages imitate Ajv’s. Implementation is the vault’s own.

    What to notice
    
  
      
    
    • Fields are optional by default: only names in required must be present. Mistyping title as tilte fails because title is required, not because tilte is unknown.
      • 
    
    • Extra fields pass unless the schema is strict: dummy_property validates until additionalProperties: false is added. Joe allows extra fields in requests and forbids them in responses.
      • 
    
    • By default only the first error is reported; with allErrors you see all three problems of listing 7.23. Note that listing 7.7’s request asks for a title field, which the enum of listing 7.5 doesn’t list: try it.
