The anagram pipeline

Think of a program as a pipeline of transformations: data flows in, each step turns it into something new, and the main function reads like the requirement. Wrap each result as {:ok, value} or {:error, reason}, and the first error flows straight through to the end.

Illustrates Topic 30, Transforming Programming (pp. 255–270): the anagram finder with “vinyl” (pp. 258–264) and error handling with an and_then bind (pp. 265–270). The book uses a full word list; this page uses a small built-in dictionary chosen to include the book’s results, plus a few more words. Implementation is the vault’s own.

word |> all_subsets_longer_than_three |> as_unique_signatures |> find_in_dictionary |> group_by_length

Controls

Up to 8 letters. The book’s example is “vinyl”.

Counters

Event log

    What to notice

    • Each step only knows its input and its output, so steps can be tested alone and reused wherever their input matches another step’s output.
    • The signature (letters sorted) is what makes the lookup cheap: all anagrams share one, so “vinyl” and any other arrangement of the same letters find the same words.
    • With an error tuple, the remaining steps are skipped rather than crashing, and the pipeline’s final value is the first error. That is the and_then bind from the book.
