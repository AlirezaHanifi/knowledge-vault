خرابکارها و پوشش حالت

برای تست کردن تست‌هایتان، آگاهانه باگ را بسازید و بررسی کنید که تست‌ها شکایت می‌کنند. و یادتان باشد اجرا شدن هر خط کافی نیست: آن چیزی که مهم است حالتهایی است که برنامه می‌تواند در آن‌ها باشد و نه خط‌هایی که دارد.

تصویری از «تست کردن تست‌ها» و «تست کردن جامع» در موضوع ۵۱، جعبه‌ی شروع pragmatic (صص. ۴۵۷–۴۵۸، tipهای ۹۲ و ۹۳)، از جمله تابع a / (a + b) کتاب با a و b از صفر تا ۹۹۹. تابع clamp و mutant‌هایش و تست‌هایش مال vault است. پیاده‌سازی مال خود vault است.

clamp(x, lo, hi): if x < lo return lo; if x > hi return hi; return x

    به چه چیزی نگاه کنید

    • یک تست تنها روی مسیر خوش قبول می‌شود، و می‌گذارد شش از هفت باگ واقعی کاشته‌شده جان سالم ببرند. مجموعه‌ی سبز چیز زیادی درباره‌ی کار کردن هشدارها نمی‌گوید.
    • تست‌هایی همان بیرون بازه، یعنی ۱۱ و ۱−، mutantهای یکی‌کم‌و‌زیاد را که مرزی را جابه‌جا می‌کنند می‌کشند؛ و تست‌هایی دور از بازه، یعنی ۴۲ و ۳−، از دستشان می‌دهند. بعضی mutant‌ها، مثل < که <= می‌شود، هم‌ارزند: همان رفتار را دارند، پس هیچ تستی نمی‌تواند بگیردشان.
    • یک خط، یک میلیون حالت: عبارت a / (a + b) فقط وقتی شکست می‌خورد که a و b هر دو صفر باشند. پوشاندن آن خط یک تست می‌برد و پیدا کردن آن حالت با شانس، حدود یک میلیون.
