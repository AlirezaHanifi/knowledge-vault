Orthogonality and the ripple of a change

In an orthogonal system, changing one thing doesn’t affect the others. The book’s test: if the requirements behind one function change dramatically, how many modules are affected? In an orthogonal system the answer is one.

Illustrates Topic 10, Orthogonality (pp. 93–103, Tips 17–18), including the mobile interface for a heating-plant controller (p. 97), global data (p. 98) and similar functions (p. 99).     What to notice

    • With no couplings every requirement lands in exactly one module: the book’s test for orthogonality.
    • A shared global (the tax rate) drags the UI and reports into a tax change, which is why the book treats global data as a source of coupling.
    • Scattered authentication is the worst ripple: one decision duplicated everywhere means changing the login provider touches every module.
