How does it scale?

Big-O doesn’t give actual times: it says how time changes as input grows. If a routine takes one second for 100 records, how long for 1,000? It depends entirely on its order.

Illustrates Topic 39, Algorithm Speed (pp. 343–351, Tips 63–64): the orders and examples from the book’s table, and its one-second, 100-to-1,000-records example (p. 345). The times here scale each formula exactly, so O(lg n) and O(n lg n) differ from the book’s rounder “about 3 s” and “some 33 s” (see the vault note in the lesson). Exponential is shown as 2ⁿ.     What to notice

    • Constant factors vanish: two O(n) routines can differ by a factor of 1,000, but both get ten times slower for ten times the data.
    • O(n²) and worse run away quickly. The book’s O(n²) example goes from one second to 100 seconds, and exponential becomes cosmic almost immediately.
    • Test your estimates: run the code at three or four sizes and see which row of this table your timings follow.
