Hunt the falsifying example

The hand-written unit tests pass. The property says that stock can’t appear or disappear: what was taken plus what is left equals what was there. Generate random orders and check it, and the computer finds the assumption you and your code shared.

Illustrates “Finding Bad Assumptions” in Topic 42, Property-Based Testing (pp. 378–383, Tip 71): the Warehouse with shoes 10, hats 2, umbrellas 0, the property, the strategies (item from shoes or hats, quantity 1–4) and the fix. The generator, the simple shrinker and the wider quantity option are the vault’s; the book uses Hypothesis. Implementation is the vault’s own.

    What to notice

    • The unit tests all pass, because they only order one hat at a time. The property fails the first time a random order asks for more hats than are in stock.
    • The bug isn’t where the property points. The test is about stock levels, but the fault is in in_stock, which only checks that there is at least one. That is the surprise the book describes.
    • Shrinking tries simpler inputs (the first item, smaller quantities) until the failure is as small as it can be: hats, 3, the book’s falsifying example. Turn it into a unit test so it can’t come back.
