Tumbling, hopping, sliding and session windows

An aggregation over an unbounded stream needs a window: a rule for which events count together. The same twenty minutes of clicks from two users give very different answers depending on whether windows have fixed boundaries, overlap, slide with the events, or follow each user’s bursts of activity.

Illustrates “Types of windows” (p. 522): the book’s one-minute tumbling, five-minute hopping with one-minute hop, five-minute sliding, and 30-minute-inactivity session examples, scaled down so twenty minutes fit on screen. The event stream is the vault’s own. Implementation is the vault’s own.

What to notice

  • Tumbling: fixed length, every event in exactly one window — implemented by rounding each timestamp down.
  • Hopping: fixed length but overlapping, so each event is counted in several windows; the result is smoother.
  • Sliding: no fixed boundaries — two events a few minutes apart share a window even if a tumbling boundary falls between them. It needs a buffer of recent events.
  • Session: no fixed length at all; a user’s window ends after a gap of inactivity. Shrink the gap and sessions split.
