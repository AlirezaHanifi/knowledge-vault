مفهوم sharding و rebalancing

مفهوم sharding داده و بار را روی ماشین‌های زیادی پخش می‌کند. دو پرسش تعیین می‌کنند که کار می‌کند یا نه: وقتی یک node اضافه می‌شود چقدر داده جابه‌جا می‌شود، و آیا بار واقعاً یکنواخت پخش می‌شود.

برای صص. ۲۵۶–۲۶۴: hash mod N، تعداد ثابت shard، consistent hashing از نوع rendezvous، و hot spot با شکل‌های ۷-۳ و ۷-۴. ده هزار کلید ساختگی؛ hash پایدار است.

به چه چیزی دقت کنید

  • روش hash mod N با تغییر N تقریباً همه‌ی کلیدها را جابه‌جا می‌کند، خیلی بیشتر از سهم 1/N که node تازه لازم دارد (ص. ۲۵۹).
  • تعداد ثابت shard shardهای کامل را جابه‌جا می‌کند، پس فقط حدود 1/N داده جابه‌جا می‌شود. توازن به اندازه‌ی shardها محدود است و nodeها نمی‌توانند از shardها بیشتر شوند (صص. ۲۵۹–۲۶۰).
  • روش rendezvous hashing هم حدود 1/N را جابه‌جا می‌کند، اما node تازه کلیدهای تکی پراکنده از همه‌ی nodeها را می‌گیرد (ص. ۲۶۳).
  • مدل key range با timestamp همه‌ی نوشتن‌ها را به shard جدیدترین بازه می‌فرستد؛ hash کردن آن‌ها را پخش می‌کند (صص. ۲۵۷–۲۵۸).
  • یک hot key تکی هر hashی را شکست می‌دهد. دو رقم تصادفی نوشتن‌هایش را بین ۱۰۰ کلید پخش می‌کند، به قیمت خواندنی که باید هر ۱۰۰ تا را بگیرد (ص. ۲۶۴). این‌که پسوند در key range کلیدها را کنار هم نگه می‌دارد مشاهده‌ی همین شبیه‌سازی است.
