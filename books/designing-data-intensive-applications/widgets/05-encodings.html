One record, four encodings

The same three-field record, encoded four ways. Textual JSON spells out every field name; MessagePack makes it binary but keeps the names; Protocol Buffers replaces names with tag numbers; Avro drops identifiers altogether and relies on the schema. Select a byte to see what it means.

Illustrates “JSON, XML, and Binary Variants”, “Protocol Buffers” and “Avro” (pp. 165–177), using the book’s example record and its sizes (81, 66, 33 and 32 bytes). The encoders are the vault’s own minimal implementations of the wire formats; the companion lab experiment reproduces the same sizes in Python.

What to notice

  
    
    
  • Field names dominate JSON and MessagePack. Count the highlighted bytes: “favoriteNumber” alone costs 14–16 bytes every time a record is written.
    • 
    
  • Protocol Buffers sends a tag, not a name. One byte packs the tag number and wire type, so renaming a field in the schema changes nothing on the wire — but changing a tag breaks every stored record.
    • 
    
  • Avro sends only values. Without the writer’s schema you can’t even tell where one field ends and the next begins; the reader resolves the writer’s schema against its own.
    • 
    
  • Numbers become variable-length. 1337 takes two bytes as a varint; small numbers take one.
