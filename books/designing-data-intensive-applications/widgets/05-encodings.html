یک رکورد، چهار encoding

یک رکورد سه‌فیلدی، با چهار encoding. قالب متنی JSON اسم همه‌ی فیلدها را می‌نویسد؛ MessagePack باینری‌اش می‌کند اما اسم‌ها را نگه می‌دارد؛ Protocol Buffers به جای اسم شماره‌ی tag می‌گذارد؛ و Avro هیچ شناسه‌ای نمی‌نویسد و به schema تکیه می‌کند. یک بایت را انتخاب کنید تا معنایش را ببینید.

برای بخش‌های «قالب JSON و XML و نسخه‌های باینری‌شان»، «قالب Protocol Buffers» و «قالب Avro» در صص. ۱۶۵–۱۷۷، با رکورد نمونه‌ی کتاب و اندازه‌هایش: ۸۱، ۶۶، ۳۳ و ۳۲ بایت. encoderها پیاده‌سازی کوچک خود vault از این wire formatها هستند؛ آزمایش همراه در lab همین اندازه‌ها را در Python بازتولید می‌کند.

userName favoriteNumber interests اسم فیلد type، tag یا طول داده‌ی مقدار

  • اسم فیلدها بیشتر حجم JSON و MessagePack را می‌گیرند. بایت‌های رنگی را بشمارید: فقط «favoriteNumber» در هر رکورد ۱۴ تا ۱۶ بایت خرج دارد.
    • 
    
  • قالب Protocol Buffers به جای اسم tag می‌فرستد. یک بایت شماره‌ی tag و wire type را با هم دارد، پس تغییر نام فیلد در schema هیچ چیز را روی سیم عوض نمی‌کند؛ اما تغییر tag همه‌ی رکوردهای ذخیره‌شده را می‌شکند.
    • 
    
  • قالب Avro فقط مقدارها را می‌فرستد. بدون writer's schema حتی نمی‌شود فهمید یک فیلد کجا تمام می‌شود و بعدی کجا شروع؛ خواننده writer's schema را با schema خودش تطبیق می‌دهد.
    • 
    
  • عددها طول متغیر پیدا می‌کنند. عدد ۱۳۳۷ به شکل varint دو بایت می‌گیرد و عددهای کوچک یک بایت.
