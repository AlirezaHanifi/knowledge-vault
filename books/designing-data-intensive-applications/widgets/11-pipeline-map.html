فصل ۱۱ در طول یک pipeline داده

این pipeline در اصل یک workflow از کارهای batch است: هر مرحله ورودی را می‌خواند و خروجی را از صفر می‌سازد. یک lens انتخاب کنید و مرحله‌ها را از دیتابیس منبع تا داشبورد طی کنید تا ببینید کجا اجرای دوباره امن است، کجا working set از حافظه بزرگ‌تر می‌شود و کجا خروجی نیمه‌کاره ممکن است دیده شود.

کل فصل را (صص. ۴۵۱–۴۸۶) روی reference stack خود vault نشان می‌دهد، یعنی یک پلتفرم داده‌ی عمومی: دیتابیس relational منبع ← loader ← لایه‌های Bronze و Silver و Gold در یک warehouse ستونی ← notebook، داشبورد و یک API. مرحله‌ها و نمره‌های ۱ تا ۵ ساده‌سازی خود vault است، و پیاده‌سازی هم.

به چه چیزی دقت کنید

  • با lens اجرای دوباره: فقط چون Bronze immutable است، Silver و Gold را می‌شود بی‌خطر از صفر دوباره ساخت؛ loader و تحویل خروجی جاهایی‌اند که اجرای دوباره خراب می‌کند.
  • با lens حافظه: موتور warehouse با داده‌ی بزرگ‌تر از حافظه کنار می‌آید؛ notebook و joinهای hash جاهایی‌اند که working set باید در حافظه جا شود.
  • با lens تحویل: خطر اصلی بین مرحله‌هاست: فایل‌های نیمه‌کاره در object store، اجرای زودهنگام با ساعت، و نوشتن ردیف‌به‌ردیف برای API.
