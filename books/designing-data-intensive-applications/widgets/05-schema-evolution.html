Writer’s schema, reader’s schema

Avro decodes with two schemas: the writer’s, used to encode the record, and the reader’s, which the application expects. Fields are matched by name; a field only the writer has is ignored, and a field only the reader has is filled from the reader’s default. Whether that works in both directions decides forward and backward compatibility.

Verdict

What to notice

  • Defaults are what make change safe. Add or remove only fields that have a default, and both directions keep working (p. 175).
  • Add without a default breaks backward compatibility: new code reading an old record has nothing to put in the field.
  • Remove without a default breaks forward compatibility: old code reading a new record misses a field it requires.
  • Renaming via an alias is backward compatible but not forward compatible — old readers don’t know the new name.
  • Protocol Buffers instead uses tag numbers: names can change freely, a tag may never be reused, and unknown tags are skipped (p. 171).
