کتابخانه/ DDIA/ فصل ۹/ مفهوم timeout

یک node کی مرده است؟

یک ناظر هر ۱۰۰ میلی‌ثانیه یک heartbeat از یک node می‌شنود. سکوت ممکن است یعنی node crash کرده، یا فقط یک packet در صف مانده یا process برای garbage collection متوقف شده. timeout کوتاه nodeهای زنده را مرده اعلام می‌کند و timeout بلند crash واقعی را دیر می‌بیند.

برای صص. ۳۵۱–۳۵۵. heartbeatها، توزیع latency و crash در ثانیه‌ی ۵۰ مدل خود vault هستند.

با این timeout

به چه چیزی دقت کنید

  • هیچ مقدار امنی نیست. هر timeout دو نمودار پایین را با هم معامله می‌کند؛ فقط می‌توانید روی منحنی جابه‌جا شوید.
  • توقف‌ها و صف‌ها تعیین‌کننده‌اند. وقتی نرخ توقف یا latency صف بالا می‌رود، فاصله‌ها دنباله‌ی بلندی پیدا می‌کنند و timeoutهای کوتاه node زنده را مرده اعلام می‌کنند (صص. ۳۵۳–۳۵۴).
  • حکم نادرست «مرده» گران است. ممکن است node هنوز مشغول کار باشد در حالی که دیگری جایش را گرفته، پس یک کار دو بار اجرا می‌شود؛ و جابه‌جا کردن بارش می‌تواند سیستمی پربار را به cascading failure بکشاند (ص. ۳۵۲).
  • اول اندازه بگیرید، بعد تطبیق بدهید. کتاب پیشنهاد می‌کند timeout را به‌صورت تجربی از زمان‌های رفت‌وبرگشت مشاهده‌شده انتخاب کنید، یا مثل Phi Accrual خودکار تنظیمش کنید (ص. ۳۵۵).
