کتابخانه/ DDIA/ فصل ۹/ مفهوم timeout
فصل ۹ · دردسرهای سیستم‌های توزیع‌شده

یک node کی مرده است؟

یک ناظر هر ۱۰۰ میلی‌ثانیه یک heartbeat از یک node می‌شنود. سکوت ممکن است یعنی node crash کرده؛ یا فقط یک packet در صف مانده یا process برای garbage collection متوقف شده. تصمیم با timeout است: اگر کوتاه باشد nodeهای زنده مرده اعلام می‌شوند، اگر بلند باشد یک crash واقعی دیده نمی‌شود.

برای بخش‌های «تشخیص fault» و «مفهوم timeout و latencyهای unbounded»، از جمله congestion و صف‌ها، در صص. ۳۵۱–۳۵۵: latencyهای بی‌کران، کران 2d + r که شبکه‌های واقعی نمی‌دهند، و timeoutهای خودتنظیم مثل Phi Accrual. heartbeatها، توزیع latency و crash در ثانیه‌ی ۵۰ مدل خود vault هستند. پیاده‌سازی مال خود vault است.

با این timeout

به چه چیزی دقت کنید

  • هیچ مقدار امنی نیست. هر timeout دو نمودار را با هم معامله می‌کند؛ فقط می‌توانید روی منحنی جابه‌جا شوید.
  • توقف‌ها و صف‌ها تعیین‌کننده‌اند. نرخ توقف یا latency صف را بالا ببرید: فاصله‌ها دنباله‌ی بلندی پیدا می‌کنند و timeoutهای کوتاه node زنده را مرده اعلام می‌کنند.
  • حکم نادرست «مرده» گران است. ممکن است node هنوز مشغول کار باشد در حالی که دیگری جایش را گرفته، پس یک کار دو بار اجرا می‌شود؛ و جابه‌جا کردن بارش می‌تواند سیستمی پربار را به cascading failure بکشاند (ص. ۳۵۲).
  • اول اندازه بگیرید، بعد تطبیق بدهید. کتاب پیشنهاد می‌کند timeout را به‌صورت تجربی از زمان‌های رفت‌وبرگشت مشاهده‌شده انتخاب کنید، یا مثل Phi Accrual خودکار تنظیمش کنید (ص. ۳۵۵).
