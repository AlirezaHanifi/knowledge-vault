Inside an LSM-tree

Writes go to an in-memory sorted table and a write-ahead log. When the memtable fills up, it is written out as an immutable sorted file (SSTable). Reads check the newest data first; compaction merges old files so reads stay cheap and overwritten values get discarded.

Illustrates “Log-Structured Storage” (pp. 118–125) and “Comparing B-Trees and LSM-Trees” (pp. 129–132). A deliberately tiny model: keys are single letters, Bloom filters have 24 bits and 2 hash functions, compaction merges all SSTables into one. Implementation is the vault’s own.

    What to notice

    • Writes are sequential appends. A put touches only memory and the log; disk files are never modified in place — only written whole and later deleted.
    • Reads may probe several files. Get a key that was written long ago: the memtable and newer SSTables are checked first. The Bloom filter lets a read skip files that definitely lack the key — but watch for false positives (“maybe”, then not found).
    • Deletes are writes. A tombstone shadows older values until compaction removes both.
    • Compaction trades write work for read cost. Watch write amplification rise as the same keys are rewritten into new SSTables.
    • The WAL is only for recovery. Crash the node: the memtable is rebuilt from the log; flushed SSTables are already durable.
