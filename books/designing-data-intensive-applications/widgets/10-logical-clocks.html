Ordering events: wall clocks, Lamport clocks, vector clocks

A reply must never be ordered before the message it answers. Wall-clock timestamps can get that wrong when clocks are skewed. A Lamport clock — a counter that jumps forward whenever it sees a larger one — always orders causes before effects; a vector clock additionally tells you which messages were concurrent.

    What to notice

    • Wall clocks break causality. With Bryce’s clock slow, his reply is stamped earlier than Aaliyah’s message — red in the first list.
    • Lamport: (counter, node). Both first messages get counter 1; Bryce, having seen 1, stamps his reply 2. Ties are broken by node name: (1, Aaliyah) < (1, Caleb) < (2, Bryce).
    • Total order, not concurrency. Lamport timestamps order concurrent messages arbitrarily; the vector clocks show that Aaliyah’s and Caleb’s messages were concurrent (amber).
    • The cost of vectors. A vector clock carries one counter per node — fine for three people, heavy for thousands of nodes (p. 422).
