Clock skew and last write wins

Last write wins keeps the value with the greatest timestamp — but the timestamp comes from the clock of whichever node accepted the write. If that clock is a few milliseconds slow, a write that clearly happened later gets an earlier timestamp and is thrown away, with no error.

What to notice

  • Causality vs timestamps. B’s increment reads x = 1, so it must come after A’s write — yet with node 3 just 3 ms slow it is stamped earlier, and node 2 keeps x = 1.
  • Silent loss. Nothing fails; the increment simply disappears. The chart shows how quickly losses climb once skew approaches the gap between dependent writes.
  • The book’s fix. Give an overwriting write a timestamp above the value it replaces (at the cost of reading it first): no write is lost, whatever the skew.
  • Better still: logical clocks and version vectors order events by causality instead of quartz crystals (pp. 364, 420).
