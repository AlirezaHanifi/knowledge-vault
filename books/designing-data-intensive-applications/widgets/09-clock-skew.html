مفهوم clock skew و last write wins

قاعده‌ی last write wins مقداری را نگه می‌دارد که بزرگ‌ترین timestamp را دارد، و timestamp از ساعت nodeی می‌آید که نوشتن را پذیرفته. اگر آن ساعت چند میلی‌ثانیه کند باشد، نوشتنی که بعدتر رخ داده timestamp زودتری می‌گیرد و بی‌صدا دور ریخته می‌شود.

برای صص. ۳۶۲–۳۶۴ و شکل ۹-۳. نمودار سمت چپ آزمایش خود vault است: ۴۰۰ نوشتن وابسته که به نوبت بین دو node می‌روند، با فاصله‌ی حدود ۵ میلی‌ثانیه.

شکل ۹-۳ با ساعت فعلی node 3

سهم نوشتن‌های گم‌شده بر حسب عقب بودن ساعت، آزمایش vault

حکم در node 2

وقتی یک نوشتن مقداری را بازنویسی می‌کند…

به چه چیزی دقت کنید

  • ترتیب علّی در برابر timestamp. افزایش B مقدار x = 1 را می‌خواند، پس بعد از نوشتن A است؛ اما وقتی node 3 فقط ۳ میلی‌ثانیه کند است، برچسب زودتری می‌خورد و node 2 مقدار x = 1 را نگه می‌دارد (ص. ۳۶۳).
  • گم شدن بی‌صدا. هیچ چیز شکست نمی‌خورد؛ افزایش فقط ناپدید می‌شود. نمودار vault نشان می‌دهد وقتی skew به فاصله‌ی بین نوشتن‌های وابسته نزدیک می‌شود، گم شدن‌ها چقدر سریع بالا می‌روند.
  • راه‌حل کتاب. به نوشتنی که بازنویسی می‌کند timestampی بالاتر از مقداری که جایگزین می‌کند بدهید؛ به قیمت این‌که اول آن را بخوانید (ص. ۳۶۳).
  • از آن هم بهتر: مفهوم logical clock رویدادها را با شمارنده مرتب می‌کند، نه با کریستال quartz (صص. ۳۶۴ و ۴۱۷).
