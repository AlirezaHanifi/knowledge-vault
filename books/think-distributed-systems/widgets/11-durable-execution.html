Restart, resume and replay

alphabet() prints a to f, one letter per step. A crash interrupts it; recovery continues it. Recovery is failure-transparent if the recovered trace is equivalent to the failure-free trace a•b•c•d•e•f•✓, and the application chooses what counts as equivalent.

Illustrates “The concept of failure-transparent recovery”, “Strategies of failure-transparent recovery” and “Durable execution” (pp. 149–155, Listings 11.2, 11.6–11.7, Figure 11.5).     What to notice

    • Restart repeats every step done before the crash, so only the restart equivalence accepts it, and only if the steps are idempotent.
    • Resume repeats the steps since the last save point; with a save point after every step, it repeats at most the step that crashed.
    • Log-based replay feeds logged outputs back instead of re-executing, so it repeats only a step that ran but wasn’t logged yet: “duplicate the last event”.
    • Nondeterminism breaks replay. If code outside a step reads the clock, the replayed run can yield a different step than the log recorded, and the runtime must stop.
