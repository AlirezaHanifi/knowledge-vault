Proposers, acceptors and a coordinator

Proposer P1 sends (+2) and proposer P2 sends (×2). Two acceptors start at 0 and apply requests in the order they arrive. The operations don’t commute, so different arrival orders leave the acceptors with different values. A coordinator that tags each request with a sequence number lets the acceptors apply them in tag order, whatever order the network delivers them in.

Illustrates “Order and time” (pp. 30–32, Figures 2.11–2.12). The random delivery orders, the seed and the trial counter are the vault’s. Implementation is the vault’s own.

    What to notice

    • Without a coordinator, an acceptor that receives (+2) then (×2) ends at 4, while one that receives (×2) then (+2) ends at 2, which is Figure 2.11.
    • With a coordinator, the order in which C happens to receive the two requests becomes the order. Either is acceptable, because the proposers never coordinated.
    • An acceptor that sees tag 1 before tag 0 knows it skipped a step and holds the request until the missing one arrives (Figure 2.12).
