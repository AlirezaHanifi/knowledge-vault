A restartable Undo log

Before each operation, the database appends its Undo to the Transaction Undo Log. After a crash, recovery runs the Undo of every uncommitted operation in reverse order. But logging and applying are separate steps, so an Undo may run for an operation that never happened, and a crash during recovery runs Undos twice. Undo must be noop and idempotent: restartable.

    What to notice

    • Crash after logging an Undo but before its operation: a relative Undo (“A += 10”) adds 10 to a balance that was never debited, creating money.
    • Crash during recovery: recovery starts over and runs the same Undos again. A relative Undo applied twice over-corrects.
    • An absolute Undo (“A := 50”, the old value) is a noop if its operation never ran and has the same effect no matter how often it runs, so recovery always restores 50 / 50.
