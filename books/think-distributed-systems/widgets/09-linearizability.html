Chapter 9 · Consistency

Is this history linearizable?

Each operation is an interval from invocation to completion. A history is linearizable if some sequential history gives the same results (sequential equivalence) and keeps every pair of non-overlapping operations in their real-time order. Operations that overlap may be ordered either way.

    What to notice

    • Figure 9.7: process A writes 10, gets OK, then reads 0. No order can put the read after the write and return 0, so it isn’t linearizable.
    • Overlap gives freedom. A read that overlaps a write may return the old or the new value; both have a valid linearization point.
    • Two reads that disagree with real time: if B reads the new value and C, starting later, reads the old one, no single order of the write explains both.
