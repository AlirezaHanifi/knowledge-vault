The behavior space of a two-participant transaction

Each participant starts working and eventually moves to committed or aborted; each step moves exactly one participant. Safety says the system must never reach a state where one committed and the other aborted. Liveness says it can’t stay in working forever. A system is correct if every possible behavior satisfies both.

Illustrates “Correctness” (pp. 9–12, Listing 1.1, Figure 1.9). The “unanimous” protocol switch, which forbids the transitions into mixed states, is the vault’s way of showing what a correct system must rule out. Implementation is the vault’s own.

    What to notice

    • Eight complete behaviors exist without coordination: either participant moves first, and each decides commit or abort. Four of them end in a mixed state and violate safety.
    • Liveness is about infinite behaviors. A behavior that stays in working forever never does anything bad, so it’s safe, but it isn’t live. Pressing “stay” models that waiting.
    • The unanimous protocol removes the transitions into mixed states. Every remaining complete behavior is safe, but liveness still requires that the participants eventually take their steps.
