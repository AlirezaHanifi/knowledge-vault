Happened-before and Lamport clocks

Event a happened before b if they’re on the same component and a came first, if a is a send and b the matching receive, or by transitivity. Otherwise they’re concurrent. A Lamport clock increments on every step and, on receive, jumps to max(own, received) + 1, which guarantees clock consistency: a → b ⇒ C(a) < C(b).

    What to notice

    • Happened-before is a partial order. Two events on different components with no chain of messages between them are concurrent, even if one was drawn further left.
    • Clock consistency holds in one direction only. Whenever a → b, C(a) < C(b). But C(a) < C(b) can also hold for concurrent events, so a Lamport timestamp alone can’t tell you that a happened before b.
    • The receive rule max(own, received) + 1 is what pulls a lagging component’s clock forward, as in Figure 2.18.
