Vector clocks and causal delivery

A vector clock holds one counter per process. Each message carries its sender’s vector, so a receiver can tell whether it has already seen everything the message depends on. If it hasn’t, the message waits in a buffer until its dependencies arrive. Comparing two vectors element by element shows whether one event happened before the other or whether they are concurrent.

    What to notice

    • Run the scenario. P2 sees M1 and then broadcasts M2, so M2 depends on M1. P3 receives M2 first and buffers it, because its clock shows that it hasn’t seen M1 yet.
    • Delivery merges clocks. Delivering a message raises the receiver’s entry for that sender, which can release buffered messages.
    • Concurrent means incomparable. If each vector is larger somewhere, neither event knew about the other. That is how replicas detect conflicting writes.
    • Detection is not resolution. Vector clocks tell you that two writes conflict, not which one should win.
