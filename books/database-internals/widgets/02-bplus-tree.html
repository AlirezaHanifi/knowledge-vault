B⁺-Tree splits and merges

A B⁺-Tree keeps values only in its leaves; internal nodes hold separator keys. Insert into a full leaf and it splits: half its keys move to a new sibling, and the first key of that sibling is copied up into the parent, which may split in turn. Delete from a leaf until it underflows and it borrows from a sibling or merges with one, pulling a separator down. The tree grows and shrinks a level only at the root.

Illustrates “B-Tree Node Splits” and “B-Tree Node Merges” (pp. 39–42) and, with ascending inserts, right-only appends (Ch. 4). The capacity, the underflow threshold (half the capacity, rounded down) and the redistribution step are the vault’s choices; the keys are random but seeded. Implementation is the vault’s own.

    What to notice

    • Splits copy a key up. In a leaf split, the new right sibling’s first key becomes the separator in the parent; in an internal split, the middle key moves up and appears only once.
    • The tree grows at the top. Height only increases when the root splits, so all leaves stay at the same depth.
    • Ascending inserts fill the right edge. With sorted keys every split happens on the rightmost leaf, and every node left behind is only half full. This is why some engines special-case right-only appends.
    • Delete can borrow before it merges. An underflowing node first takes a key from a sibling with spare keys; only if neither can spare one do the two merge and the parent loses a separator.
