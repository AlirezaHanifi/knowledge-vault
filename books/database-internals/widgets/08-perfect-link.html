Chapter 8 · Introduction and Overview

From fair-loss to perfect links

A fair-loss link may lose, duplicate or reorder messages, and the sender can’t tell which happened. Acknowledgments plus retransmits (a stubborn link) make sure nothing is lost forever, but retries create duplicates. Sequence numbers let the receiver hold early messages in a reorder buffer and drop anything it has already processed. The result is a perfect link: reliable delivery, no duplication, no creation.

Illustrates “Links” (pp. 182–186): fair-loss links, message acknowledgments, message retransmits, problems with retransmission, message order and exactly-once delivery.     What to notice

    • Fair-loss alone loses messages and processes duplicates and reordered messages as they come.
    • ACKs and retransmits eventually deliver everything, but a lost ACK makes the sender resend a message that was already processed: duplicates go up.
    • Sequence numbers fix both. Messages above n_consecutive + 1 wait in the reorder buffer; anything at or below n_processed is a duplicate and is discarded.
    • Set loss to 0 and delay jitter to 0: all three links then behave the same; the machinery only matters when the network misbehaves.
