Paxos, round by round

A proposer first sends Prepare(n) to a majority of acceptors. Each one promises to ignore proposals numbered lower than n and reports any value it has already accepted. The proposer then sends Accept!(n, v), where v is the value of the highest-numbered accepted proposal it heard about, or its own if there is none. A value is chosen once a majority accepts the same proposal.

Illustrates “Paxos Algorithm”, “Quorums in Paxos” and “Failure Scenarios” (pp. 286–291, Figures 14-3 to 14-6). The scenarios follow the book’s figures: in the fourth, proposer P1 retries with number 3 to show that a later proposer prefers the more recent accepted proposal. The dueling scenario’s length and the five-acceptor setup are the vault’s. The acceptor rules are the book’s. Implementation is the vault’s own.

    What to notice

    • Figure 14-4. P1’s value reached only A1 before P1 crashed. P2’s quorum includes A1, which reports (1, V1), so P2 must propose V1, not its own value.
    • Figure 14-5. P2’s quorum misses A1, nobody reports an accepted value, and P2 gets V2 chosen. V1 was accepted by one acceptor but never chosen, so this is still safe.
    • Figure 14-6. A1 accepted V1 and crashed; V2 is chosen without it. When P1 retries and reaches A1 again, it sees (1, V1) and (2, V2) and picks the higher-numbered one, so the decision stands.
    • Dueling proposers keep invalidating each other’s promises with higher numbers, and nobody finishes. Random backoff lets one of them complete a round.
