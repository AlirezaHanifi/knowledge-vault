LSM Trees: merge-iteration and compaction

An LSM Tree buffers writes in a memtable and flushes it as an immutable sorted table. Updates and deletes (tombstones) never touch older tables, so a read merge-iterates several tables and keeps the newest record per key. Compaction merges tables to bound that read cost. Leveled compaction keeps key ranges disjoint from level 1 on; size-tiered merges tables of similar size.

    What to notice

    • Reads get more expensive between compactions. Every table in L0 or in a size tier may contain the key, so all of them are checked; from L1 on, leveled compaction needs at most one table per level.
    • Compaction rewrites data. Records rewritten per user write is the write amplification; leveled compaction usually pays more of it in exchange for fewer tables per read.
    • Shadowed records waste space until compaction drops them: compare records stored with live keys.
    • Tombstones live until the bottom. A tombstone is dropped only when the merge reaches the oldest data, otherwise the deleted value could resurrect.
