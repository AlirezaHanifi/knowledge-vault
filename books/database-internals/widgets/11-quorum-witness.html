Quorums and witness replicas

With N replicas, a write needs W acknowledgments and a read R responses. If R + W > N, every read set overlaps every write set, so some node in the read set has the latest write. A witness replica normally records only the fact that a write happened. When a copy replica is down, a witness takes the record temporarily.

Illustrates “Tunable Consistency”, “Quorums” and “Witness Replicas” (pp. 235–237). The book’s condition for witnesses to keep the availability of full copies is majority quorums with at least one copy replica in every quorum; the widget checks both. Which live nodes a request reaches is the vault’s choice (copies first for writes, seeded random for reads). Implementation is the vault’s own.

    What to notice

    • R + W > N is about overlap, not majorities. W = 1, R = N also overlaps, but then every replica must be up for a read.
    • Witnesses save storage, not availability. With majorities and at least one copy in every quorum, n copies plus m witnesses tolerate as many failures as n + m copies.
    • Fail a copy and write. A witness in the write quorum temporarily stores the record; Repair brings the copy back up to date and the witness drops it again.
    • Too many witnesses break the guarantee. If a quorum could consist of witnesses only, a read might know a newer version exists but find no node holding its data.
