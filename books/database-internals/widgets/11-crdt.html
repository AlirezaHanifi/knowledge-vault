CRDT: شمارنده و مجموعه‌ای که همیشه merge می‌شود

یک CRDT اجازه می‌دهد replicaها مستقل از هم، حتی وسط partition، به‌روزرسانی بپذیرند و بعد بی‌تعارض merge شوند. در G-Counter هر replica فقط خانه‌ی خودش را در یک بردار زیاد می‌کند؛ merge بیشینه‌ی هر خانه را برمی‌دارد و مقدار، جمع خانه‌هاست. PN-Counter دو بردار P و N دارد تا کم کردن هم ممکن شود. مجموعه با یک add set و یک remove set حذف را هم پشتیبانی می‌کند.

تصویری از «Strong Eventual Consistency and CRDTs» (صص. ۲۳۸–۲۴۰). مثال سه‌گره‌ای G-Counter عیناً همان مثال کتاب است (ص. ۲۳۹)؛ replicaها با نام A، B و C همان Node 1 تا ۳ کتاب‌اند. partition، عنصرها و ترتیب عملیات صحنه‌ی vault است. mergeها state-based است، یعنی کل حالت رد و بدل می‌شود، مثل مثال شمارنده‌ی کتاب. پیاده‌سازی از خود vault است.

شمارنده‌ها

به چه چیزی دقت کنید

  • هیچ به‌روزرسانی گم نمی‌شود. افزایش‌های دو طرف partition همه بعد از merge می‌مانند، چون هر replica فقط خانه‌ی خودش را می‌نویسد (صص. ۲۳۸–۲۳۹).
  • ترتیب مهم نیست. حالت‌ها هر بار به ترتیبی متفاوت رد و بدل می‌شوند و نتیجه همیشه یکی است، چون merge جابه‌جاپذیر است (ص. ۲۳۹). بیشینه و اجتماع idempotent هم هستند، پس تکرار یک merge هم چیزی را خراب نمی‌کند (توضیح vault).
  • G-Counter کم نمی‌شود. کم کردن فقط PN-Counter را تغییر می‌دهد که مقدارش جمع P منهای جمع N است (ص. ۲۳۹).
  • حذف از مجموعه همیشگی است. فقط عنصری که در add set هست می‌تواند به remove set برود و مقدار مجموعه، add set منهای remove set است؛ پس عنصر حذف‌شده با اضافه کردن دوباره برنمی‌گردد (ص. ۲۴۰).
