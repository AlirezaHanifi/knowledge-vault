Merkle trees: find the difference, not the data

Comparing replicas record by record is too expensive. A Merkle tree hashes ranges of records into leaves, and each parent hashes its children. Two replicas first compare root hashes. If they differ, they descend only into the subtrees whose hashes differ, and stream just the leaf ranges that mismatch.

    What to notice

    • Matching roots end the comparison after one hash. With no divergence that is all the repair costs.
    • Only differing branches are explored. One changed key costs one hash per level, not one per key.
    • Bigger leaf ranges make a smaller tree but stream more data: a whole range is sent even if only one key in it differs.
    • Hashes need a scan. Building the tree reads the whole table, and any change invalidates the hashes up to the root (p. 248).
