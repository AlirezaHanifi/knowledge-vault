# AGENTS.md — how this vault works

A knowledge vault turns technical books into interactive lessons. Everything about one book lives in `books/<slug>/`; shared code lives in `assets/` and `scripts/`. This file is the single set of rules; the skills in `.claude/skills/` are the step-by-step workflows.

## Layout

| Path | Contents |
|---|---|
| `books/<slug>/README.md` | Front matter (metadata), *About*, chapter map, *Chapters* table, *Key concepts* glossary, optional *Companion resources* (outside talks, readings, courses), *Source* |
| `books/<slug>/book.pdf`, `cover.jpg` | Source PDF (gitignored, local only) and its cover image (committed) |
| `books/<slug>/chapters/NN-*.md` | Chapter notes — **the source of truth** |
| `books/<slug>/chapters/NN-*.html` | Lessons, generated from the notes |
| `books/<slug>/figures/NN-MM.png`, `figures.tsv` | The book's own figures, cropped from the PDF (Figure N-M → `NN-MM.png`); the TSV records each crop's PDF page and box so it can be re-rendered |
| `books/<slug>/widgets/NN-*.html` | Hand-built simulations (NN = chapter illustrated), embedded in lessons |
| `books/<slug>/lab/NN-*/` | Experiments: one script + README with expected output |
| `books/<slug>/framework.md` | Cross-chapter synthesis, one per book once its chapters are written: the vault's own whole-to-part framework (map → principles → decision guide → stack → chapter map, see [`add-book/framework.md`](.claude/skills/add-book/framework.md)), rendered to `framework.html` as a slide deck and linked from the hub and from each lesson's last slide |
| `books/<slug>/index.html`, `index.html` | Book hub and library page, generated |
| `practice/reference-stack.md` | The reference stack: a generic data-team platform that *In practice* callouts are written against |
| `assets/` | `kit.css`/`kit.js` (design tokens, controls, simulation helpers), `site.css`/`site.js` (lessons and hubs), `vendor/mermaid.min.js` |
| `scripts/` | `build.py` (Markdown → HTML), `validate.py` (the gatekeeper; CI runs it), `pdf.py` (outline, text and page search in a source PDF), `fa_terms.py` + `fa_terms.tsv` (Persian checks: banned coined terms, Latin-first lines; `--fix` rewrites terms) |

## Rules

1. **Never fabricate book content.** Titles, outlines, page numbers, examples, figures and quotations come from the source named in the book's front matter, and carry printed page references. If you can't verify something, leave it out. Quotations are rare, word-for-word and under ~15 words.
2. **Keep the author's content and the vault's apart.** In a chapter note, everything above *Beyond the book* restates the book; outside material and interpretation go below it or in a `> **Vault note:**` callout; links to everyday data work go in a `> **In practice:**` callout (with a `**Your turn:**` question and `*Answer:*`) written against `practice/reference-stack.md`, which stays generic — this repository is public, so no company, partner, internal system or private figure is named. Quiz questions, simulations and experiments are the vault's own and say so, with the pages they illustrate. Book figures are the author's content: each carries its label and printed page.
3. **Markdown is the source; HTML is generated.** Edit chapter notes and book READMEs, then run `scripts/build.py`. Never hand-edit generated pages (they start with a "Generated by" comment). Widgets are the only hand-written HTML. Figures are cropped with `scripts/pdf.py figure`, never edited by hand.
4. **One fact, one home.** Metadata lives in front matter; the chapter list lives in the book README's *Chapters* table; ideas that recur across chapters get one row in the book's *Key concepts* glossary, not separate files.
5. **Everything is connected.** Every widget is embedded in at least one chapter with a `> **Try it:**` line; every experiment is linked from a chapter's *Connections* as `**Run it:**`.
6. **Chapter notes keep a fixed shape** (the lesson generator depends on these headings): *Summary* → *Key takeaways* → *Section outline* → *Notes* (optional chapter introduction, then `###` per book section and `####` per subsection — each becomes a slide; show the book's own figure where it explains a mechanism better than words, and prefer tables and Mermaid diagrams to long prose) → *Trade-offs at a glance* → *Beyond the book* → *Connections* → *Check yourself*. Template: [`chapter.md`](.claude/skills/write-chapter/chapter.md).
7. **Offline and dependency-free.** Pages use only `assets/` (classic scripts, no CDNs, no modules, no build tools beyond `scripts/build.py`); they must work from `file://`. Experiments use the Python standard library with seeded randomness.
8. **Accessible and themable.** Native labelled controls, `aria-live` logs for state changes, meaning never by colour alone, colours only from kit tokens (light and dark), reduced motion respected.
9. **Small and real.** No empty folders, stubs or placeholders; create a file with its first real content. Prefer extending an existing note, widget or kit helper over adding a new one.
10. **Done means checked.** `python3 scripts/build.py && python3 scripts/validate.py` pass; experiments match their README output; changed pages were opened in a browser with a clean console (see `check-site`).

## Names and vocabularies

- Slugs: lowercase `a–z`, `0–9`, hyphens. Book folder = full title, no edition unless two coexist. Chapter note = `NN-title-slug.md`.
- Book front matter: `title`, `edition`, `authors`, `publisher`, `year`, `toc_source`, `toc_verified` required; `short_title`, `published`, `pages`, `isbn_print`, `isbn_online`, `source_file`, `cover`, `lang`, `kind` optional. `kind` is `book` (the default) or `articles` for a web post series; the library page lists the two kinds in separate groups, and an `articles` source cites each post's own section headings instead of page numbers.
- Framework front matter (`framework.md`): `book`, `title` required; `lang` and `post_map` (the `##` heading of its chapter-map section, which lessons link to) optional. Everything in it is the vault's reading, so every claim links the chapters it rests on; its widgets are numbered `00-`.
- Chapter front matter: `book` (= folder), `chapter` (= NN), `title` required; `pages` recommended; an `articles` post also sets `source_url`, the post's own address, which its lesson links to on the first and last slides.
- Lesson language: a chapter note may set `lang: fa` to be written in Persian, with `translated_title` for the chapter title (`title` stays the book's own). Its lesson is laid out right to left with Persian labels and the bundled Vazirmatn font (`assets/fonts/`). Everything a reader sees is Persian, including the `##` headings (the Persian names in `H2_ALIASES` in `scripts/build.py`), the book's section titles, outline items and *Try it*/*Run it* link titles, and prose numbers use Persian digits. English stays only for technical terms (written in English whenever practitioners say them in English: cloud, replica, leader, cache, process, concurrency, immutable — never a coined Persian equivalent, never both forms; `scripts/fa_terms.tsv` lists the banned calques and the validator enforces it), code, Mermaid diagrams in chapter notes, terminal output and the vault's inline markers (`**In practice:**`, `**Your turn:**`, `*Answer:*`, `**Try it:**`, `**Run it:**`, `*Figure N-M (p. X):*`) and page references `(p. N)`, which the validator reads; the lesson shows markers, page references and figure labels in Persian. No Persian line starts with a Latin word (it would render left to right on GitHub). A Persian book's widgets are Persian too (`<html lang="fa" dir="rtl">`; the kit supplies the font, control labels and Persian digits), and so are its lab READMEs, except the terminal output. Parentheses are kept for page references and real asides, not for glosses or examples. The book README of a Persian book sets `lang: fa` too: it is written in Persian with the Persian `##` names in `BOOK_H2_ALIASES` (`scripts/build.py`), and its hub page is Persian; only the book's title, the authors' names and the publisher stay English, and the reading-map diagram is Persian with every label opening with a Persian word. The full guide is [`write-chapter/persian.md`](.claude/skills/write-chapter/persian.md). Every other file in the repository stays English.
- No reading progress, status or reader history is tracked — not in files, not in the browser. Lessons always open at the slide in the URL (or the first).

## Why it is built this way

- **Per-book folders** keep a book's notes, lessons, simulations and experiments together; adding a book never touches another book's files.
- **Generated lessons** give a polished, interactive reading experience without duplicating content: the notes stay readable on GitHub and remain the only thing to maintain.
- **Concept notes were folded** into each book's glossary: they mostly repeated chapter material and needed constant cross-linking.
- **Simulations are separate pages** embedded by iframe, so each one also works on its own and can be reused by several lessons.
- **Mermaid is vendored** (one file in `assets/vendor/`) so diagrams render offline; GitHub renders the same diagrams natively.

## Source PDFs

Each book's PDF sits at `books/<slug>/book.pdf` and stays out of git (`.gitignore`: `books/*/*.pdf`). With poppler installed, `scripts/pdf.py` prints the bookmark outline with printed page numbers, extracts the text, finds the printed pages on which phrases occur, lists figure captions and crops figures into `figures/` — see the `add-book`, `fact-check` and `add-figures` skills.
