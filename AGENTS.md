# AGENTS.md — how this vault works

A knowledge vault turns technical books into interactive lessons. Everything about one book lives in `books/<slug>/`; shared code lives in `assets/` and `scripts/`. This file is the single set of rules; the skills in `.claude/skills/` are the step-by-step workflows.

## Layout

| Path | Contents |
|---|---|
| `books/<slug>/README.md` | Front matter (metadata), *About*, chapter map, *Chapters* table, *Key concepts* glossary, optional *Companion resources* (outside talks, readings, courses), *Source* |
| `books/<slug>/book.pdf`, `cover.jpg` | Source PDF (gitignored, local only) and its cover image (committed) |
| `books/<slug>/chapters/NN-*.md` | Chapter notes — **the source of truth** |
| `books/<slug>/chapters/NN-*.html` | Lessons, generated from the notes |
| `books/<slug>/widgets/NN-*.html` | Hand-built simulations (NN = chapter illustrated), embedded in lessons |
| `books/<slug>/lab/NN-*/` | Experiments: one script + README with expected output |
| `books/<slug>/index.html`, `index.html` | Book hub and library page, generated |
| `assets/` | `kit.css`/`kit.js` (design tokens, controls, simulation helpers), `site.css`/`site.js` (lessons and hubs), `vendor/mermaid.min.js` |
| `scripts/` | `build.py` (Markdown → HTML), `validate.py` (the gatekeeper; CI runs it), `pdf.py` (outline, text and page search in a source PDF) |

## Rules

1. **Never fabricate book content.** Titles, outlines, page numbers, examples, figures and quotations come from the source named in the book's front matter, and carry printed page references. If you can't verify something, leave it out. Quotations are rare, word-for-word and under ~15 words.
2. **Keep the author's content and the vault's apart.** In a chapter note, everything above *Beyond the book* restates the book; outside material and interpretation go below it or in a `> **Vault note:**` callout. Quiz questions, simulations and experiments are the vault's own and say so, with the pages they illustrate.
3. **Markdown is the source; HTML is generated.** Edit chapter notes and book READMEs, then run `scripts/build.py`. Never hand-edit generated pages (they start with a "Generated by" comment). Widgets are the only hand-written HTML.
4. **One fact, one home.** Metadata lives in front matter; the chapter list lives in the book README's *Chapters* table; ideas that recur across chapters get one row in the book's *Key concepts* glossary, not separate files.
5. **Everything is connected.** Every widget is embedded in at least one chapter with a `> **Try it:**` line; every experiment is linked from a chapter's *Connections* as `**Run it:**`.
6. **Chapter notes keep a fixed shape** (the lesson generator depends on these headings): *Summary* → *Key takeaways* → *Section outline* → *Notes* (optional chapter introduction, then `###` per book section and `####` per subsection — each becomes a slide; prefer tables and Mermaid diagrams to long prose) → *Trade-offs at a glance* → *Beyond the book* → *Connections* → *Check yourself*. Template: [`chapter.md`](.claude/skills/write-chapter/chapter.md).
7. **Offline and dependency-free.** Pages use only `assets/` (classic scripts, no CDNs, no modules, no build tools beyond `scripts/build.py`); they must work from `file://`. Experiments use the Python standard library with seeded randomness.
8. **Accessible and themable.** Native labelled controls, `aria-live` logs for state changes, meaning never by colour alone, colours only from kit tokens (light and dark), reduced motion respected.
9. **Small and real.** No empty folders, stubs or placeholders; create a file with its first real content. Prefer extending an existing note, widget or kit helper over adding a new one.
10. **Done means checked.** `python3 scripts/build.py && python3 scripts/validate.py` pass; experiments match their README output; changed pages were opened in a browser with a clean console (see `check-site`).

## Names and vocabularies

- Slugs: lowercase `a–z`, `0–9`, hyphens. Book folder = full title, no edition unless two coexist. Chapter note = `NN-title-slug.md`.
- Book front matter: `title`, `edition`, `authors`, `publisher`, `year`, `toc_source`, `toc_verified` required; `short_title`, `published`, `pages`, `isbn_print`, `isbn_online`, `source_file`, `cover` optional.
- Chapter front matter: `book` (= folder), `chapter` (= NN), `title` required; `pages` recommended.
- No reading progress, status or reader history is tracked — not in files, not in the browser. Lessons always open at the slide in the URL (or the first).

## Why it is built this way

- **Per-book folders** keep a book's notes, lessons, simulations and experiments together; adding a book never touches another book's files.
- **Generated lessons** give a polished, interactive reading experience without duplicating content: the notes stay readable on GitHub and remain the only thing to maintain.
- **Concept notes were folded** into each book's glossary: they mostly repeated chapter material and needed constant cross-linking.
- **Simulations are separate pages** embedded by iframe, so each one also works on its own and can be reused by several lessons.
- **Mermaid is vendored** (one file in `assets/vendor/`) so diagrams render offline; GitHub renders the same diagrams natively.

## Source PDFs

Each book's PDF sits at `books/<slug>/book.pdf` and stays out of git (`.gitignore`: `books/*/*.pdf`). With poppler installed, `scripts/pdf.py` prints the bookmark outline with printed page numbers, extracts the text, and finds the printed pages on which phrases occur — see the `add-book` and `fact-check` skills.
